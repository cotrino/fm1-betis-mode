# FM1 Betis Mode

Unofficial Betis-themed firmware for **M-VAVE FM1**, built from the official
[FM1 Open V13 source + binary SDK](https://github.com/m-vave/fm1_open).
The hardware package and browser emulator use the same application sources.

- [Online emulator and firmware workbench](https://cotrino.github.io/fm1-betis-mode/)
- [Download flashable firmware](https://cotrino.github.io/fm1-betis-mode/FM1_BETIS_MODE.fwsc)
- [Matching source + SDK archive](https://cotrino.github.io/fm1-betis-mode/source.zip)
- [Firmware validation report](https://cotrino.github.io/fm1-betis-mode/firmware-report.json)
- [Run browser acceptance tests](https://cotrino.github.io/fm1-betis-mode/verify-emulator.html)

**Build-verified does not mean hardware-tested.** The package is generated by
the official packager with its boot/update resources, flash layout, build
identity and recovery image. No physical FM1 has been flashed or tested.
Back up projects and samples before installing. This is a community
modification, not an M-VAVE-endorsed release.

## Betis controls

The 240x240 RGB565 TFT starts at the **Manque Pierda** dashboard, with a green
theme, the supplied shield/Palmerin artwork, a tempo animation and MIDI-activity
jump/flash. Press **HOME+FX** to return to it from another page.

| Control | Dashboard action |
| --- | --- |
| SELECT | Select one of the eight tracks |
| Parameter knob 1: PASION | DX7 FM feedback (0-7), not available on non-FM tracks |
| Parameter knob 2: OLE REV | Selected track's reverb send |
| Parameter knob 3: DUENDE | Selected track's delay send |
| Parameter knob 4: BPM | Internal tempo, clamped to 60-180 |
| SCL | Toggle E Phrygian-dominant tuning / equal temperament |
| ARP | Toggle the selected track's official arpeggiator; hold for settings |
| PLAY | Play/stop the sequencer, including the crowd percussion on track 8 |
| SAVE | Open the official project save UI; no automatic persistent writes |
| HOME | Original eight-track overview |

The scale is **E F G# A B C D**, implemented with the official per-track
whole-cent tuning API. Original MIDI note identities remain independent, so
neighboring keys that quantize to the same pitch do not share note-off state.
Alt tuning is left unchanged. The default project enables track 1's arpeggiator
and includes an original synthesized 16-step 808 kick/clap/hat crowd rhythm.
Loading a saved project restores its own tuning, sounds, patterns and arp.

## Preserved official features

The six-operator FM, 303, 808, PSG, pluck and sampler engines, eight tracks,
USB/BLE/TRS MIDI, Bluetooth and USB audio, project/sample storage, and recovery
workbench are retained. The browser uses the upstream portable synth kernels
and an AudioWorklet, not the earlier two-operator demo. Radio discovery,
board timing, actual Flash writes, analog output and battery behavior still
need device validation.

**Native sound-control adaptation:** the early project draft requested
standalone drive/chorus DSP. This release deliberately uses the official FM
feedback and reverb/delay sends rather than replacing the native audio engine
with an unverified demo. These dashboard controls do not pretend to be a
new saturation or chorus implementation.

## Reproduce the build (Windows x64)

Requires PowerShell 5.1+, Git, `curl.exe`, and `tar.exe`; no system-wide compiler
installation or administrator rights are needed:

```powershell
git clone https://github.com/cotrino/fm1-betis-mode.git
Set-Location fm1-betis-mode
powershell -NoProfile -ExecutionPolicy Bypass -File .\Build.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\Verify.ps1
```

The bootstrap downloads and checksum-verifies **JieLi 2.5.2** and **WASI SDK
27** into `.tools/`. JieLi 2.5.3 does not match this SDK's compiler hashes.
Existing compatible installations can be reused with `FM1_PI32_TOOLCHAIN` and
`FM1_WASI_SDK`. The vendor SDK itself is not modified; its integrity checks,
linker/ABI/SRAM checks and source packager all run normally.

Outputs in `docs/`:

- `FM1_BETIS_MODE.fwsc`: flashable package.
- `index.html`: self-contained emulator, updater and stock V15 recovery UI.
- `simulator.wasm`: independently testable browser module.
- `source.zip`: exact corresponding sources, SDK and build/install scripts.
- reports, notices and `SHA256SUMS.txt`.

The upstream commit and changed vendor files are recorded in `upstream.json`.
The generated workbench adds branding/navigation to the upstream HTML;
the packaged firmware and Wasm payloads remain unchanged and are checked
against the downloadable files.

## Browser verification

Serve the repository locally:

```powershell
python -m http.server 8080 --bind 127.0.0.1
```

Open `http://localhost:8080/docs/` for the workbench or
`http://localhost:8080/tests/verify-emulator.html` for executable acceptance
tests. Tests boot the real Wasm application and check tuning, TFT pixels, BPM
bounds, ARP, finite bounded FM audio, independent note release, silence after
release, project/tuning round-trips, and sequenced percussion.

Click the workbench's audio control before playing. Web MIDI requires a
compatible browser on HTTPS or localhost and explicit permission. Device
firmware updates are a separate explicit action in the workbench: none are
performed during builds or emulator tests. Keep the device powered throughout
an update; use the included original V15 recovery option if needed, following
the official recovery instructions.

GitHub Pages serves the committed `docs/` directory from `main`. The Windows
CI workflow rebuilds and verifies packages and uploads them as an artifact;
publishing a changed build requires committing its refreshed `docs/`.
